= Gyroscope Calibration
:description: Gyroscope calibration algorithms — KnownFrame, Turntable, and the turntable-free "Easy" calibrator — for estimating bias, scale-factor, cross-coupling, and g-dependent bias, plus quaternion step integrators.
:keywords: gyroscope calibration, turntable calibration, Easy calibrator, Tedaldi, g-dependent bias, quaternion integration, Runge-Kutta, angular rate calibration

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

The `com.irurueta.navigation.inertial.calibration.gyroscope` package (86 classes) estimates gyroscope
bias stem:[\mathbf{b}_g], the scale-factor/cross-coupling matrix stem:[\mathbf{M}_g], and the
*g-dependent cross-bias* matrix stem:[\mathbf{G}_g] (extra bias driven by the specific force the
accelerometer senses — typically from mass unbalance in the sensing element):

[stem]
++++
\boldsymbol{\Omega}_{\text{meas}} = \mathbf{b}_{g} + \left(\mathbf{I}_{3} + \mathbf{M}_{g}\right)\boldsymbol{\Omega}_{\text{true}} + \mathbf{G}_{g}\,\mathbf{f}_{\text{true}} + \mathbf{w}
++++

The page first lists the algorithm families, then derives the equations each family solves
(<<known-frame>>, <<turntable>>, <<easy>>, <<g-dependent>>), and finally compares the quaternion step
integrators the "Easy" family relies on (<<quaternion-integration>>). The generic machinery (linear least
squares, Levenberg-Marquardt, robust wrappers, the static-interval pipeline) is explained once in
xref:calibration/algorithms.adoc[] and only referenced here.

NOTE: Javadoc and source links for every class used in the examples below are collected in the
<<Class Reference>> table at the end of this page.

`AccelerometerDependentGyroscopeCalibrator` is the common interface marking calibrators that also need
(already-calibrated) accelerometer bias and cross-coupling, because the g-dependent term requires the true
specific force. `TurntableGyroscopeCalibrator`, `KnownBiasTurntableGyroscopeCalibrator`, `EasyGyroscopeCalibrator`
and `KnownBiasEasyGyroscopeCalibrator` implement it.

The `KnownFrame` classes are linear in the unknowns and each measurement gives three equations, so
stem:[\lceil 21/3 \rceil = 7] and stem:[\lceil 18/3 \rceil = 6] measurements suffice, and the minimum is the same for
the linear and the non-linear classes and does not depend on the common-axis flag. The turntable and Easy
calibrators keep a minimum of one more than the number of unknowns: the `Turntable` classes produce one scalar
residual per measurement, and for `Easy` this is a deliberately conservative minimum (each sequence now provides
three equations, see <<easy>>). Defaults: `commonAxisUsed = true` and `estimateGDependentCrossBiases = true` for
`Turntable` and `KnownBiasTurntable`; `commonAxisUsed = false` and `estimateGDependentCrossBiases = false` for
`Easy`, `KnownBiasEasy` and their robust variants (they follow the paper, see <<easy>>); `commonAxisUsed = false`
for the `KnownFrame` classes. With the `Easy` defaults the minimum is therefore 13 sequences (`Easy`, 12
unknowns) or 10 sequences (`KnownBiasEasy`, 9 unknowns).

=== `KnownFrame` example

Each measurement pairs a `BodyKinematics` sample with the known ECEF frame (position, orientation, velocity)
at which it was taken. `KnownFrameGyroscopeNonLinearLeastSquaresCalibrator` refines an initial
stem:[\mathbf{b}_g], stem:[\mathbf{M}_g] and stem:[\mathbf{G}_g] guess through non-linear least squares:

[source,java]
----
// each measurement bundles a body kinematics sample with the known frame it was taken at
final Collection<StandardDeviationFrameBodyKinematics> measurements = new ArrayList<>();
// ...
measurements.add(new StandardDeviationFrameBodyKinematics(measuredKinematics, ecefFrame, ecefFrame,
        timeIntervalSeconds, specificForceStandardDeviation, angularRateStandardDeviation));

// initial bg, Mg, Gg guesses close to the expected solution
final Matrix initialBias = new Matrix(3, 1);
final Matrix initialMg = new Matrix(3, 3);
final Matrix initialGg = new Matrix(3, 3);

final var calibrator = new KnownFrameGyroscopeNonLinearLeastSquaresCalibrator(measurements, false, initialBias,
        initialMg, initialGg, this);

calibrator.calibrate();

final Matrix estimatedBg = calibrator.getEstimatedBiasesAsMatrix();
final Matrix estimatedMg = calibrator.getEstimatedMg();
final Matrix estimatedGg = calibrator.getEstimatedGg();
----

=== `Turntable` example

Measurements only need position (the turntable's fixed location) plus the known, constant rotation rate —
no per-measurement orientation is required, since the turntable enforces it:

[source,java]
----
final NEDPosition position = new NEDPosition(latitude, longitude, height);
final double rotationRate = Constants.EARTH_ROTATION_RATE; // rad/s
final double timeInterval = TurntableGyroscopeCalibrator.DEFAULT_TIME_INTERVAL; // seconds

final Collection<StandardDeviationBodyKinematics> measurements = new ArrayList<>();
// ...
measurements.add(new StandardDeviationBodyKinematics(measuredKinematics, specificForceStandardDeviation,
        angularRateStandardDeviation));

final Matrix initialBias = new Matrix(3, 1);
final Matrix initialMg = new Matrix(3, 3);
final Matrix initialGg = new Matrix(3, 3);

// accelerometer bias/cross-coupling are only used when the g-dependent term is estimated
// (setAccelerometerBias / setAccelerometerMa); here it is disabled with the second flag
final var calibrator = new TurntableGyroscopeCalibrator(position, rotationRate, timeInterval, measurements,
        true, false, initialBias, initialMg, initialGg);

calibrator.calibrate();

final Matrix estimatedBg = calibrator.getEstimatedBiasesAsMatrix();
final Matrix estimatedMg = calibrator.getEstimatedMg();
final Matrix estimatedGg = calibrator.getEstimatedGg();
----

[#known-frame]
== KnownFrame calibrators: linear in the unknowns

With a known frame at every measurement the true angular rate stem:[\boldsymbol{\Omega}_{\text{true},k}] and the true
specific force stem:[\mathbf{f}_{\text{true},k}] are computed from the frame (the library derives both from the
ECEF frames of the measurement with its kinematics estimator). Moving the known stem:[\boldsymbol{\Omega}_{\text{true}}]
to the left of the error model of this page makes every unknown appear linearly:

[stem]
++++
\boldsymbol{\Omega}_{\text{meas},k} - \boldsymbol{\Omega}_{\text{true},k}
= \mathbf{b}_g + \mathbf{M}_g\,\boldsymbol{\Omega}_{\text{true},k} + \mathbf{G}_g\,\mathbf{f}_{\text{true},k}
++++

With the common z-axis assumption stem:[\mathbf{M}_g] is upper triangular (six entries), otherwise it has nine.
The code orders the unknowns as stem:[(b_x, b_y, b_z, s_x, s_y, s_z, m_{xy}, m_{xz}, m_{yz}, \mathbf{g}_{1\bullet}, \mathbf{g}_{2\bullet}, \mathbf{g}_{3\bullet})]
(common axis; the general case has three more entries of stem:[\mathbf{M}_g]) and each measurement contributes a three-row block. Using stem:[\boldsymbol{\Omega}_{\text{true}} = (\Omega_x,\Omega_y,\Omega_z)] and
stem:[\mathbf{f}_{\text{true}} = (f_x,f_y,f_z)], the first block of columns is stem:[\mathbf{I}_3] (bias), the next ones multiply the
entries of stem:[\mathbf{M}_g] by the components of stem:[\boldsymbol{\Omega}_{\text{true}}] (as in
xref:calibration/algorithms.adoc#linear-model[the linear model]) and the last nine are stem:[\mathbf{I}_3 \otimes \mathbf{f}_{\text{true}}^{T}].

Written out row by row for the common-axis case with the full stem:[\mathbf{G}_g]:

[stem]
++++
\begin{aligned}
\Omega_{\text{meas},x}-\Omega_x &= b_x + s_x\Omega_x + m_{xy}\Omega_y + m_{xz}\Omega_z + g_{11}f_x + g_{12}f_y + g_{13}f_z\\
\Omega_{\text{meas},y}-\Omega_y &= b_y + s_y\Omega_y + m_{yz}\Omega_z + g_{21}f_x + g_{22}f_y + g_{23}f_z\\
\Omega_{\text{meas},z}-\Omega_z &= b_z + s_z\Omega_z + g_{31}f_x + g_{32}f_y + g_{33}f_z
\end{aligned}
++++

Stacking the blocks gives stem:[\mathbf{A}\boldsymbol{\theta} = \mathbf{y}] exactly as in
xref:calibration/algorithms.adoc#linear-model[the linear model], with 21 columns (18 with the common axis).
`KnownFrameGyroscopeLinearLeastSquaresCalibrator` solves it in one step. The non-linear
`KnownFrameGyroscopeNonLinearLeastSquaresCalibrator` runs Levenberg-Marquardt on the *same* linear model, but
feeds the fitter the analytical Jacobian (the entries of stem:[\mathbf{A}_k] above, no numerical differentiation),
so it needs an initial guess and then converges almost immediately. `KnownBiasAndFrame...` drops the first block
(stem:[\mathbf{b}_g] subtracted from the left side instead): 18 or 15 unknowns.

[#turntable]
== Turntable calibrators: constant known rate and Earth rate

=== Idea

A turntable spinning at a constant, known rate stem:[\omega_t] gives a reference *magnitude* but not the
direction of the true rate in the sensor frame, in the same way a static accelerometer gives only the magnitude
stem:[\lVert\mathbf{g}\rVert]. The calibrators therefore reuse the norm-based formulation of
xref:calibration/algorithms.adoc#nonlinear-model[the non-linear model], with the known rate in place of the
gravity norm.

=== Earth rate removal

Both the turntable and the Earth rotate, so the code first removes the Earth-rate vector. At the given
position (`NEDPosition` or `ECEFPosition`) it builds a frame whose body axes coincide with the local
navigation axes (identity attitude), asks the kinematics estimator for the angular rate that frame senses, and
takes that vector stem:[\boldsymbol{\Omega}_{\text{ref}}] (the Earth rate resolved on those axes) as the Earth contribution. Every
sample is shifted by it:

[stem]
++++
\boldsymbol{\Omega}'_{k} = \boldsymbol{\Omega}_{\text{meas},k} - \boldsymbol{\Omega}_{\text{ref}},
\qquad
\text{target: } \lVert\boldsymbol{\Omega}_{\text{true}}\rVert^{2} = \omega_t^{2}
++++

so the squared turntable rate stem:[\omega_t^2] is the observation stem:[y_k] of every measurement.
(`DEFAULT_TURNTABLE_ROTATION_RATE` is the Earth rate and `DEFAULT_TIME_INTERVAL` is 0.02 s, defaults only.)
Only the magnitude of the rate enters, so the sense of rotation does not matter.

=== Model and bias handling

Using the reparametrization of the non-linear model, stem:[\mathbf{M} = \mathbf{I}_3 + \mathbf{M}_g],
stem:[\mathbf{b} = \mathbf{M}^{-1}\mathbf{b}_g], stem:[\mathbf{G} = \mathbf{M}^{-1}\mathbf{G}_g], the error model
becomes stem:[\boldsymbol{\Omega}_{\text{meas}} = \mathbf{M}(\boldsymbol{\Omega}_{\text{true}} + \mathbf{b} + \mathbf{G}\mathbf{f}_{\text{true}})].
Solving for the true rate and taking its squared norm gives the prediction fitted by Levenberg-Marquardt:

[stem]
++++
h_k(\mathbf{b},\mathbf{M},\mathbf{G}) =
\left\lVert \mathbf{M}^{-1}\boldsymbol{\Omega}'_{k} - \mathbf{b} - \mathbf{G}\,\mathbf{f}_{\text{true},k} \right\rVert^{2},
\qquad
\chi^{2} = \sum_k \left(\frac{\omega_t^{2} - h_k}{\sigma_k}\right)^{2}
++++

stem:[\mathbf{f}_{\text{true},k}] is the measured specific force corrected with the accelerometer bias and
cross-coupling supplied by the user, and stem:[\sigma_k] is the angular-rate standard deviation of the
measurement. Geometrically the corrected samples lie on a sphere of radius stem:[\omega_t]; in measurement space
this is an ellipsoid whose *center is the gyroscope bias* and whose shape is stem:[\mathbf{M}\mathbf{M}^{T}]. The bias
is therefore not eliminated by differencing but estimated as the ellipsoid center, jointly with the scale
factors and cross-couplings (the same picture as hard and soft iron in xref:calibration/magnetometer.adoc[]).
`TurntableGyroscopeCalibrator` fits stem:[\mathbf{b}], stem:[\mathbf{M}] (and stem:[\mathbf{G}] by default) with the
Jacobian obtained by numerical `GradientEstimator`, not analytically.
`KnownBiasTurntableGyroscopeCalibrator` removes the bias unknowns: the supplied bias is subtracted inside the
same expression, leaving only stem:[\mathbf{M}] (and stem:[\mathbf{G}]) to estimate. If `estimateGDependentCrossBiases` is false the
stem:[\mathbf{G}\mathbf{f}] term is dropped. With the common z-axis flag stem:[\mathbf{M}] is upper triangular, which also
removes the rotational ambiguity of the norm-only cost described in xref:calibration/algorithms.adoc#nonlinear-model[the non-linear model].

NOTE: The measurements must cover several directions of the true rate (for example by mounting the IMU in
different orientations on the table). If every sample shares the same direction the ellipsoid cannot be
recovered and the fit is rank deficient.

[#easy]
== Easy calibrators: integrated rotation versus gravity direction

The pipeline that produces the sequences is described in
xref:calibration/algorithms.adoc#tedaldi[the Tedaldi et al. method] and
xref:calibration/intervals-and-generators.adoc[]. This section gives the per-sequence residual that
`EasyGyroscopeCalibrator` actually minimizes.

For sequence stem:[k] let stem:[\bar{\mathbf{f}}^{-}_k] and stem:[\bar{\mathbf{f}}^{+}_k] be the mean specific forces of
the static bracket before and after the motion. They are corrected with the accelerometer bias and
cross-coupling supplied by the user and normalized, so only the gravity direction remains:

[stem]
++++
\mathbf{u}^{-}_k = \frac{\hat{\mathbf{f}}^{-}_k}{\lVert\hat{\mathbf{f}}^{-}_k\rVert},
\qquad
\mathbf{u}^{+}_k = \frac{\hat{\mathbf{f}}^{+}_k}{\lVert\hat{\mathbf{f}}^{+}_k\rVert}
++++

For a candidate stem:[(\mathbf{b}, \mathbf{M}, \mathbf{G})] (same reparametrization as above) every timed sample of
the sequence is corrected with the gyroscope model, including its own corrected specific force:

[stem]
++++
\boldsymbol{\Omega}_{\text{true},j} = \mathbf{M}^{-1}\boldsymbol{\Omega}_{\text{meas},j} - \mathbf{b} - \mathbf{G}\,\mathbf{f}_{\text{true},j}
++++

The corrected rates are integrated with the Runge-Kutta step integrator (this choice is fixed inside the
calibrator, it is not configurable) starting from the identity attitude, giving the attitude change
stem:[\mathbf{q}_k] of the body over the motion. Gravity is fixed in the world, so in body axes it turns by the
inverse rotation, and the residual is the *three-component* difference between the predicted and the measured
final direction:

[stem]
++++
\mathbf{r}_k(\mathbf{b},\mathbf{M},\mathbf{G}) =
\mathbf{u}^{+}_k - \mathbf{R}_k^{T}\mathbf{u}^{-}_k,
\qquad
\chi^{2} = \sum_k \left\lVert \frac{\mathbf{r}_k}{\sigma_{u,k}} \right\rVert^{2}
++++

where stem:[\mathbf{R}_k] is the rotation matrix of stem:[\mathbf{q}_k] (so stem:[\mathbf{R}_k^{T}\mathbf{u}^{-}_k]
is stem:[\mathbf{q}_k^{-1}] applied to stem:[\mathbf{u}^{-}_k]) and stem:[\sigma_{u,k}] is the standard deviation of
the gravity direction of the sequence, `BodyKinematicsSequence.getGravityDirectionStandardDeviation()`
(dimensionless). Each sequence therefore contributes *three equations* instead of one scalar distance. The fit is
done by `LevenbergMarquardtMultiVariateFitter`: the inputs of each observation are the two normalized static
directions, which stay fixed, and the model output is stem:[\mathbf{R}_k^{T}\mathbf{u}^{-}_k], compared with
stem:[\mathbf{u}^{+}_k]. The Jacobian is still numerical, but it is obtained with the `JacobianEstimator` of
`irurueta-numerical` configured with a relative step and a minimum step of `1e-7`, so the step is
`1e-7 * max(1, |p|)` (with the default, purely relative step, the step vanishes for parameters near zero, which
made the fit singular on noiseless data whose true parameters are zero). When a sequence does not carry a gravity-direction standard deviation, it is estimated from
the items (accelerometer noise and integrated gyroscope noise), and a value of 1 is used if nothing is available.
The robust variants already scored each sequence with the norm of this three-component residual.

[#easy-defaults]
*Defaults.* Following the paper, `EasyGyroscopeCalibrator`, `KnownBiasEasyGyroscopeCalibrator` and their robust
variants now default to `commonAxisUsed = false` (full stem:[\mathbf{M}_g], nine entries) and
`estimateGDependentCrossBiases = false`. The upper-triangular form is only valid for the sensor that defines the
body frame, which is the accelerometer, not the gyroscope; and stem:[\mathbf{G}_g] is weakly observable from
gravity references alone. Both remain available as options (`setCommonAxisUsed(true)`,
`setEstimateGDependentCrossBiases(true)`). The Turntable calibrators keep their previous defaults.

Differences from the paper (see the Tedaldi notes on the algorithms page): the gyroscope bias is an
*unknown of this fit* (nothing is subtracted beforehand), the residual is a distance between unit vectors rather
than between integrated vectors in the paper's own parametrization, and the defaults are the general (full)
matrix without the g-dependent term (see <<easy-defaults>>). The accelerometer must be calibrated first because
stem:[\mathbf{u}^{\pm}_k] and stem:[\mathbf{f}_{\text{true},j}] depend on it. `KnownBiasEasyGyroscopeCalibrator` is the same
fit with the bias taken from the caller (6 to 18 unknowns, 9 by default, see <<minimums>>).

=== `Easy` example

Each sequence carries the specific-force readings from the static brackets before/after, plus the
timed angular-rate samples captured in between:

[source,java]
----
final List<BodyKinematicsSequence<StandardDeviationTimedBodyKinematics>> sequences = new ArrayList<>();
// ...
final var sequence = new BodyKinematicsSequence<StandardDeviationTimedBodyKinematics>();
sequence.setBeforeMeanSpecificForceCoordinates(beforeMeanFx, beforeMeanFy, beforeMeanFz);
sequence.setAfterMeanSpecificForceCoordinates(afterMeanFx, afterMeanFy, afterMeanFz);

final List<StandardDeviationTimedBodyKinematics> items = new ArrayList<>();
// ...
items.add(new StandardDeviationTimedBodyKinematics(measuredKinematics, timestampSeconds,
        specificForceStandardDeviation, angularRateStandardDeviation));
sequence.setItems(items);
sequences.add(sequence);

// known accelerometer bias/cross-coupling, needed because bg-dependent bias
// requires the true specific force
final Matrix initialBias = new Matrix(3, 1);
final Matrix initialMg = new Matrix(3, 3);
final Matrix initialGg = new Matrix(3, 3);
final Matrix accelerometerBias = new Matrix(3, 1);
final Matrix accelerometerMa = new Matrix(3, 3);

final var calibrator = new EasyGyroscopeCalibrator(sequences, true, false, initialBias, initialMg,
        initialGg, accelerometerBias, accelerometerMa);

calibrator.calibrate();

final Matrix estimatedBg = calibrator.getEstimatedBiasesAsMatrix();
final Matrix estimatedMg = calibrator.getEstimatedMg();
final Matrix estimatedGg = calibrator.getEstimatedGg();
----

[#g-dependent]
== The g-dependent matrix

stem:[\mathbf{G}_g] captures the part of the bias that follows the specific force (typically a mass unbalance in
the sensing element): the term stem:[\mathbf{G}_g\mathbf{f}_{\text{true}}] adds nine unknowns. It is observable only if
the specific force changes *independently* of the angular-rate information, so the data must be gathered in
several attitudes. How each family estimates it:

* `KnownFrame`: exactly as in the block above, nine extra columns stem:[\mathbf{I}_3\otimes\mathbf{f}_{\text{true}}^{T}]
  (stored row by row: stem:[g_{11}, g_{12}, g_{13}, g_{21}, \dots]) multiply the known true specific force.
* `Turntable` and `Easy`: through stem:[\mathbf{G} = \mathbf{M}^{-1}\mathbf{G}_g] inside the non-linear model, where the specific force is
  the measured one corrected by the accelerometer bias and cross-coupling. The calibrator reports
  stem:[\mathbf{G}_g = \mathbf{M}\mathbf{G}] after the fit. This is why the accelerometer has to be calibrated
  before the gyroscope (`AccelerometerDependentGyroscopeCalibrator`).
* Disable it (`estimateGDependentCrossBiases = false`) when the data have little specific-force diversity or when
  the minimum counts in <<minimums>> cannot be met; the g-term is then assumed zero.

[#quaternion-integration]
== Quaternion step integrators

Integrating angular rate over a dynamic interval means numerically solving the quaternion kinematic
differential equation

[stem]
++++
\dot{\mathbf{q}} = \tfrac{1}{2}\,\boldsymbol{\Omega}(\boldsymbol{\omega})\,\mathbf{q},
\qquad
\boldsymbol{\Omega}(\boldsymbol{\omega}) =
\begin{bmatrix}
0 & -\omega_x & -\omega_y & -\omega_z\\
\omega_x & 0 & \omega_z & -\omega_y\\
\omega_y & -\omega_z & 0 & \omega_x\\
\omega_z & \omega_y & -\omega_x & 0
\end{bmatrix}
++++

(the matrix stem:[\boldsymbol{\Omega}] is exactly the one built by `QuaternionStepIntegrator.computeOmegaSkew`; it
satisfies stem:[\boldsymbol{\Omega}(\boldsymbol{\omega})^2 = -\lVert\boldsymbol{\omega}\rVert^2\mathbf{I}_4]).
`QuaternionStepIntegrator` defines the strategy interface; `QuaternionIntegrator` drives it over a sequence:
for consecutive items it calls the step with the previous rate stem:[\boldsymbol{\omega}_0], the current rate
stem:[\boldsymbol{\omega}_1] and stem:[\Delta t] equal to the timestamp difference, starting from the identity or a given
attitude. Every step ends with a re-normalization of the quaternion. Six schemes exist (selected with
`QuaternionStepIntegratorType`, default `RUNGE_KUTTA`).

=== Step equations

In the formulas below stem:[\mathbf{q}_0] is the attitude at the start of the step, stem:[\mathbf{q}_1] the result
(before normalization), stem:[\boldsymbol{\Omega}_0 = \boldsymbol{\Omega}(\boldsymbol{\omega}_0)],
stem:[\boldsymbol{\Omega}_1 = \boldsymbol{\Omega}(\boldsymbol{\omega}_1)], stem:[\bar{\boldsymbol{\omega}} = (\boldsymbol{\omega}_0+\boldsymbol{\omega}_1)/2]
and stem:[\bar{\boldsymbol{\Omega}} = \boldsymbol{\Omega}(\bar{\boldsymbol{\omega}})]. Define
stem:[F(\mathbf{q},\boldsymbol{\Omega}) = \tfrac{1}{2}\boldsymbol{\Omega}\mathbf{q}].

*Euler* (`EulerQuaternionStepIntegrator`): only the rate at the start of the step is used.

[stem]
++++
\mathbf{q}_1 = \mathbf{q}_0 + \Delta t\,F(\mathbf{q}_0,\boldsymbol{\Omega}_0)
++++

*Mid-point* (`MidPointQuaternionStepIntegrator`): a half Euler step with the start rate, then a full step with the
slope evaluated at the half-step state using the average rate.

[stem]
++++
\mathbf{k}_1 = F(\mathbf{q}_0,\boldsymbol{\Omega}_0),\quad
\mathbf{k}_2 = F\!\left(\mathbf{q}_0 + \tfrac{\Delta t}{2}\mathbf{k}_1,\ \bar{\boldsymbol{\Omega}}\right),\quad
\mathbf{q}_1 = \mathbf{q}_0 + \Delta t\,\mathbf{k}_2
++++

*Runge-Kutta* (`RungeKuttaQuaternionStepIntegrator`): classic RK4 where the rate is stem:[\boldsymbol{\omega}_0] at the start,
stem:[\bar{\boldsymbol{\omega}}] for both mid-step slopes and stem:[\boldsymbol{\omega}_1] at the end.

[stem]
++++
\begin{aligned}
\mathbf{k}_1 &= F(\mathbf{q}_0,\boldsymbol{\Omega}_0), &
\mathbf{k}_2 &= F(\mathbf{q}_0 + \tfrac{\Delta t}{2}\mathbf{k}_1,\bar{\boldsymbol{\Omega}}),\\
\mathbf{k}_3 &= F(\mathbf{q}_0 + \tfrac{\Delta t}{2}\mathbf{k}_2,\bar{\boldsymbol{\Omega}}), &
\mathbf{k}_4 &= F(\mathbf{q}_0 + \Delta t\,\mathbf{k}_3,\boldsymbol{\Omega}_1),\\
\mathbf{q}_1 &= \mathbf{q}_0 + \Delta t\left(\tfrac{1}{6}\mathbf{k}_1 + \tfrac{1}{3}\mathbf{k}_2 + \tfrac{1}{3}\mathbf{k}_3 + \tfrac{1}{6}\mathbf{k}_4\right)
\end{aligned}
++++

*Yuan* (`YuanQuaternionStepIntegrator`): the closed-form rotation for a constant rate equal to the average
(exact matrix exponential, using stem:[\boldsymbol{\Omega}^2 = -\lVert\boldsymbol{\omega}\rVert^2\mathbf{I}]). With
stem:[\theta = \lVert\bar{\boldsymbol{\omega}}\rVert\Delta t], and stem:[\operatorname{sinc}(x) = \sin x / x] (taken as 1 when stem:[\theta \le 10^{-15}]):

[stem]
++++
\mathbf{q}_1 = \left[\cos\tfrac{\theta}{2}\,\mathbf{I}_4 + \tfrac{\Delta t}{2}\operatorname{sinc}\!\left(\tfrac{\theta}{2}\right)\bar{\boldsymbol{\Omega}}\right]\mathbf{q}_0
++++

*Suh* (`SuhQuaternionStepIntegrator`): a truncated expansion that combines the two rates with weights stem:[\tfrac34] and
stem:[-\tfrac14] and adds second and third order terms in stem:[\Delta t]:

[stem]
++++
\mathbf{q}_1 = \left[\mathbf{I}_4 + \tfrac{3}{4}\Delta t\,\boldsymbol{\Omega}_1 - \tfrac{1}{4}\Delta t\,\boldsymbol{\Omega}_0
- \tfrac{\lVert\boldsymbol{\omega}_1\rVert^2\Delta t^2}{6}\mathbf{I}_4
- \tfrac{\Delta t^2}{24}\boldsymbol{\Omega}_1\boldsymbol{\Omega}_0
- \tfrac{\lVert\boldsymbol{\omega}_1\rVert^2\Delta t^3}{48}\boldsymbol{\Omega}_1\right]\mathbf{q}_0
++++

*Trawny* (`TrawnyQuaternionStepIntegrator`): matrix exponential of the rate extrapolated by its first derivative
stem:[\dot{\boldsymbol{\omega}} = (\boldsymbol{\omega}_1-\boldsymbol{\omega}_0)/\Delta t], plus a commutator correction:

[stem]
++++
\mathbf{q}_1 = \left[\exp\!\left(\tfrac{\Delta t}{2}\left(\boldsymbol{\Omega}_1 + \tfrac{\Delta t}{2}\boldsymbol{\Omega}(\dot{\boldsymbol{\omega}})\right)\right)
+ \tfrac{\Delta t^2}{48}\left(\boldsymbol{\Omega}_1\boldsymbol{\Omega}_0 - \boldsymbol{\Omega}_0\boldsymbol{\Omega}_1\right)\right]\mathbf{q}_0
++++

The Suh and Trawny formulas are the ones of the cited papers (xref:reference.adoc#suh2010[[suh2010\]],
xref:reference.adoc#trawny2005[[trawny2005\]]), restated; the code evaluates them as written above.

image::calibration/quaternion-integrator-error.svg[Measured final attitude error versus step size for the six quaternion step integrators on a smoothly varying angular rate: Euler, Suh and Trawny have slope one, mid-point Runge-Kutta and Yuan slope two,560,380]

The orders in the table come from a numerical experiment run for this page, not from the library tests: the six
formulas above were applied to stem:[\boldsymbol{\omega}(t) = 2\,(\sin 2t + 0.3,\ \cos 3t,\ 0.5 + \sin t)^{T}] rad/s over 2 s with
the rate sampled at both ends of each step, the result compared with a fine reference, and the slope of the
log-log error read for 10 to 160 steps. For a constant rate the same experiment gave slope 4 for Runge-Kutta and Suh, slope 2
for Euler and mid-point, and zero error (machine precision) for Yuan and Trawny.

NOTE: Suh and Trawny are designed to *predict* the next interval from the previous and the current rate
(the weights stem:[\tfrac34,-\tfrac14] and the term stem:[\boldsymbol{\Omega}(\dot{\boldsymbol{\omega}})] extrapolate the rate to the middle of the *next* step). `QuaternionIntegrator`
instead passes the rates at both ends of the interval being integrated, so for these two integrators the rate is
extrapolated beyond the interval and the experiment shows first-order accuracy; feeding the same formulas the previous
rate and the current rate to advance to the next instant gave second-order accuracy. Prefer Runge-Kutta, Yuan or
mid-point with `QuaternionIntegrator`, and note that the choice matters little when the sampling is fast
compared with the rate dynamics (the typical gyroscope case).

`EasyGyroscopeCalibrator` always integrates its sequences with the Runge-Kutta scheme.

=== Integrating a sequence directly

`QuaternionStepIntegrator.create(type)` builds the strategy for one scheme; `QuaternionIntegrator`
drives it step-by-step across an entire `BodyKinematicsSequence` to obtain the final attitude:

[source,java]
----
// integrate a whole sequence in one call, choosing the RK4 scheme
final Quaternion initialAttitude = new Quaternion(); // identity
final Quaternion finalAttitude = QuaternionIntegrator.integrateGyroSequenceAndReturnNew(sequence,
        initialAttitude, QuaternionStepIntegratorType.RUNGE_KUTTA);

// or drive a single integration step manually
final QuaternionStepIntegrator stepIntegrator =
        QuaternionStepIntegrator.create(QuaternionStepIntegratorType.RUNGE_KUTTA);
final Quaternion result = new Quaternion();
stepIntegrator.integrate(initialAttitude, previousWx, previousWy, previousWz, currentWx, currentWy,
        currentWz, dt, result);
----
