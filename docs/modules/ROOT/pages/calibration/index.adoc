= IMU Calibration
:description: Overview of IMU sensor calibration: the shared bias, scale-factor, and cross-coupling error model for accelerometers, gyroscopes, and magnetometers, and a map of the calibration package.
:keywords: IMU calibration, sensor error model, bias, scale factor, cross-axis coupling, accelerometer calibration, gyroscope calibration, magnetometer calibration, robust estimation

NOTE: This documentation was generated with the assistance of AI. Please report any inaccuracies.

The `com.irurueta.navigation.inertial.calibration` package (and its `accelerometer`, `gyroscope`,
`magnetometer`, `bias`, `generators`, `intervals`, and `noise` sub-packages) estimates the systematic
errors of an accelerometer, gyroscope, and/or magnetometer — bias, scale factor, and cross-axis coupling
— and, once known, corrects ("fixes") raw sensor readings back to their true values.

This package is by far the largest in the library (around 280 classes). Rather than one page per class,
this documentation groups classes by *what they do*, since the vast majority of classes are boilerplate
variants (different robust outlier-rejection strategies, different measurement orderings, unit
conversions) of a much smaller number of distinct algorithms.

[#error-model]
== The sensor error model

Every calibratable sensor in this library (accelerometer, gyroscope, magnetometer) is assumed to follow
the same linear error model: a fixed bias, plus a matrix of scale-factor and cross-coupling errors
applied to the true signal, plus noise stem:[\mathbf{w}]. For the accelerometer:

[stem]
++++
\mathbf{f}_{\text{meas}} = \mathbf{b}_{a} + \left(\mathbf{I}_{3} + \mathbf{M}_{a}\right)\mathbf{f}_{\text{true}} + \mathbf{w}
++++

The gyroscope additionally picks up a *g-dependent* bias driven by the specific force sensed by the
accelerometer (typically caused by mass unbalance in the spinning/vibrating element):

[stem]
++++
\boldsymbol{\Omega}_{\text{meas}} = \mathbf{b}_{g} + \left(\mathbf{I}_{3} + \mathbf{M}_{g}\right)\boldsymbol{\Omega}_{\text{true}} + \mathbf{G}_{g}\,\mathbf{f}_{\text{true}} + \mathbf{w}
++++

and the magnetometer follows the accelerometer's form, with "hard iron" playing the role of bias and
"soft iron" playing the role of cross-coupling:

[stem]
++++
\mathbf{b}_{\text{meas}} = \mathbf{b}_{m} + \left(\mathbf{I}_{3} + \mathbf{M}_{m}\right)\mathbf{b}_{\text{true}} + \mathbf{w}
++++

image::calibration/sensor-error-model.svg[Sensor error model: bias offset plus scale-factor and cross-coupling misalignment,560,320]

Here stem:[\mathbf{M}] is the *full* 3x3 matrix with the scale-factor errors on the diagonal and the
cross-coupling terms off it, and the model applies stem:[\mathbf{I}_3+\mathbf{M}] to the true signal, so
stem:[\mathbf{M}=\mathbf{0}] is an ideal sensor. The noise stem:[\mathbf{w}] is white, with a per-sample
standard deviation stem:[\sigma=\text{root-PSD}/\sqrt{\tau}] for sampling interval stem:[\tau] (see
xref:calibration/noise-and-bias.adoc#psd[PSD and root-PSD]); it is estimated separately from bias and
matrices, never by the calibrators themselves.

*Calibration* means estimating stem:[\mathbf{b}] and stem:[\mathbf{M}] (and, for the gyroscope,
stem:[\mathbf{G}_g]) from measurements taken at known or partially-known references. *Fixing* means
applying the inverse of this model to a raw reading once those parameters are known, to recover
stem:[\mathbf{x}_{\text{true}}] (see xref:calibration/fixers.adoc[]).

NOTE: stem:[\mathbf{f}_{\text{meas}}], stem:[\boldsymbol{\Omega}_{\text{meas}}], and
stem:[\mathbf{b}_{\text{meas}}] above are always resolved about *body-frame* axes — the raw sensor
reading itself is never "in NED." NED only appears as one of two interchangeable ways to describe the
*known frame/position* some calibrators need alongside a measurement: `FrameBodyKinematics` (see
xref:calibration/data-model.adoc[]) stores that frame internally as `ECEFFrame` and exposes an
NED-converted view via `getNedFrame()`/`setNedFrame()`, and calibrator families such as
`KnownPositionAccelerometerCalibrator` (xref:calibration/accelerometer.adoc[]) and
`TurntableGyroscopeCalibrator` (xref:calibration/gyroscope.adoc[]) accept a position as either
`NEDPosition` or `ECEFPosition` — neither is mandatory. Only the magnetometer's WMM-position families
(xref:calibration/magnetometer.adoc[]) and the xref:calibration/noise-and-bias.adoc[bias estimators]
require geodetic (NED-style latitude/longitude/height) position, since that is what
xref:wmm/index.adoc[the WMM] and xref:estimators/gravity.adoc[gravity models] are keyed on.

[WARNING]
====
Do not confuse the point above (the *resolving* frame for a known position, which is flexible) with the
*body*-frame axis convention of stem:[\mathbf{f}_{\text{meas}}], stem:[\boldsymbol{\Omega}_{\text{meas}}],
and stem:[\mathbf{b}_{\text{meas}}] themselves, which is *not* flexible: every equation and every
`Ma`/`Mg`/`Gg`/`Mm` matrix in this package assumes the raw sensor vector already follows Groves'
forward-right-down (FRD) body convention (§2.1.4, xref:reference.adoc#book-groves[[book-groves\]]) — see
xref:estimators/index.adoc[the same warning on the estimators page] for the exact conversion to apply if
your IMU instead reports an ENU-aligned body convention. This library performs no such conversion itself;
getting it wrong will not raise an error, only wrong bias/scale-factor/cross-coupling estimates.
====

[#calibrator-families]
== Which calibrator family uses which algorithm

Which algorithm a calibrator runs depends on what is *known* about each measurement: the full reference
signal, only its norm, or nothing but the raw motion. The names below are the class-name stems; each
page of the sensor family lists the concrete classes.

[cols="2,3,2",options="header"]
|===
|Family |What is known |Algorithm and sensor page

|`KnownFrame`, `KnownBiasAndFrame` (accelerometer, gyroscope, magnetometer; the magnetometer's version is
`KnownHardIronAndFrame`)
|Position, orientation and (for the gyroscope) angular rate of the body at every measurement, so the
true signal is known as a vector. Linear and non-linear least-squares variants exist.
|xref:calibration/algorithms.adoc#linear-model[Linear least squares] (the non-linear variants minimise the
same residual with an analytical Jacobian, see xref:calibration/algorithms.adoc#nonlinear-model[]).
Pages: xref:calibration/accelerometer.adoc[], xref:calibration/gyroscope.adoc[],
xref:calibration/magnetometer.adoc[].

|`KnownGravityNorm`, `KnownBiasAndGravityNorm`, `KnownPosition`, `KnownBiasAndPosition` (accelerometer);
`KnownMagneticFluxDensityNorm`, `KnownHardIronMagneticFluxDensityNorm`, `KnownPositionAndInstant`,
`KnownHardIronPositionAndInstant` (magnetometer)
|Only the *norm* of the true signal: a given gravity norm, the gravity model evaluated at a known
position, or the WMM field magnitude at a known position and instant. Orientation is unknown.
|xref:calibration/algorithms.adoc#nonlinear-model[Non-linear least squares] (Levenberg-Marquardt over the
norm residual; the Jacobian is estimated numerically). Pages: xref:calibration/accelerometer.adoc[],
xref:calibration/magnetometer.adoc[].

|`Turntable`, `KnownBiasTurntable` (gyroscope)
|The IMU spins flat on a turntable at constant rate; the true angular-rate norm is known, orientation and
position are not.
|xref:calibration/algorithms.adoc#nonlinear-model[Non-linear least squares], using the norm of the
angular rate. Page: xref:calibration/gyroscope.adoc[].

|`Easy`, `KnownBiasEasy` (gyroscope)
|Nothing external: static-moving-static sequences recorded by hand, with gravity as the only reference.
|xref:calibration/algorithms.adoc#tedaldi[Tedaldi et al. method]: integrates the angular rate across each
sequence and compares the rotated gravity direction. It estimates the gyroscope bias inside the same fit
(except in the `KnownBias` variant) and, as in the paper, estimates a full (general) gyroscope matrix without the g-dependent term by default. Page:
xref:calibration/gyroscope.adoc[].

|`Robust...` wrappers (every family above)
|The same inputs, but some measurements may be outliers.
|xref:calibration/algorithms.adoc#robust-estimation[Robust estimation]: RANSAC, MSAC, LMedS, PROSAC or
PROMedS around the base calibrator.
|===

TIP: The quantities that feed these calibrators come from the preprocessing stage in
xref:calibration/intervals-and-generators.adoc[], and the root-PSD and approximate-bias estimators in
xref:calibration/noise-and-bias.adoc[] seed or complement them. Once calibrated, the readings are corrected
with the xref:calibration/fixers.adoc#inverse-model[fixers].

== Why so many classes per algorithm?

Every non-trivial calibration algorithm in `accelerometer`, `gyroscope`, and `magnetometer` appears in up
to *six* forms:

[mermaid]
....
flowchart LR
    A["Known&amp;lt;X&amp;gt;...Calibrator\n(base: assumes every measurement is trustworthy)"] --> B["RANSACRobust...\n(random sample consensus)"]
    A --> C["MSACRobust...\n(RANSAC + soft cost function)"]
    A --> D["LMedSRobust...\n(least median of squares)"]
    A --> E["PROSACRobust...\n(RANSAC + measurement quality ordering)"]
    A --> F["PROMedSRobust...\n(LMedS + measurement quality ordering)"]
....

The base (non-robust) calibrator is the one that actually implements the algorithm's math — it assumes
every input measurement can be trusted. The five `Robust*` classes wrap it with an outlier-rejection
strategy from `irurueta-numerical-computing`'s robust-estimator framework, useful when some measurements
(e.g. from a noisy or disturbed static interval) might be bad. This documentation describes each
algorithm's math once and lists all six forms in a summary table, rather than repeating the same
equations six times.
