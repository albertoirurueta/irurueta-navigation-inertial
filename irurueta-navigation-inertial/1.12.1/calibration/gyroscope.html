Gyroscope Calibration

This documentation was generated with the assistance of AI. Please report any inaccuracies.

The com.irurueta.navigation.inertial.calibration.gyroscope package (86 classes) estimates gyroscope bias , the scale-factor/cross-coupling matrix , and the g-dependent cross-bias matrix (extra bias driven by the specific force the accelerometer senses — typically from mass unbalance in the sensing element):

The page first lists the algorithm families, then derives the equations each family solves (KnownFrame calibrators: linear in the unknowns, Turntable calibrators: constant known rate and Earth rate, Easy calibrators: integrated rotation versus gravity direction, The g-dependent matrix), and finally compares the quaternion step integrators the "Easy" family relies on (Quaternion step integrators). The generic machinery (linear least squares, Levenberg-Marquardt, robust wrappers, the static-interval pipeline) is explained once in Calibration algorithms and only referenced here.

Javadoc and source links for every class used in the examples below are collected in the Class Reference table at the end of this page.

The KnownFrame classes are linear in the unknowns and each measurement gives three equations, so and measurements suffice, and the minimum is the same for the linear and the non-linear classes and does not depend on the common-axis flag. The turntable and Easy calibrators keep a minimum of one more than the number of unknowns: the Turntable classes produce one scalar residual per measurement, and for Easy this is a deliberately conservative minimum (each sequence now provides three equations, see Easy calibrators: integrated rotation versus gravity direction). Defaults: commonAxisUsed = true and estimateGDependentCrossBiases = true for Turntable and KnownBiasTurntable; commonAxisUsed = false and estimateGDependentCrossBiases = false for Easy, KnownBiasEasy and their robust variants (they follow the paper, see Easy calibrators: integrated rotation versus gravity direction); commonAxisUsed = false for the KnownFrame classes. With the Easy defaults the minimum is therefore 13 sequences (Easy, 12 unknowns) or 10 sequences (KnownBiasEasy, 9 unknowns).

KnownFrame example

Each measurement pairs a BodyKinematics sample with the known ECEF frame (position, orientation, velocity) at which it was taken. KnownFrameGyroscopeNonLinearLeastSquaresCalibrator refines an initial , and guess through non-linear least squares:

// each measurement bundles a body kinematics sample with the known frame it was taken at
final Collection<StandardDeviationFrameBodyKinematics> measurements = new ArrayList<>();
// ...
measurements.add(new StandardDeviationFrameBodyKinematics(measuredKinematics, ecefFrame, ecefFrame,
        timeIntervalSeconds, specificForceStandardDeviation, angularRateStandardDeviation));

// initial bg, Mg, Gg guesses close to the expected solution
final Matrix initialBias = new Matrix(3, 1);
final Matrix initialMg = new Matrix(3, 3);
final Matrix initialGg = new Matrix(3, 3);

final var calibrator = new KnownFrameGyroscopeNonLinearLeastSquaresCalibrator(measurements, false, initialBias,
        initialMg, initialGg, this);

calibrator.calibrate();

final Matrix estimatedBg = calibrator.getEstimatedBiasesAsMatrix();
final Matrix estimatedMg = calibrator.getEstimatedMg();
final Matrix estimatedGg = calibrator.getEstimatedGg();

Turntable example

Measurements only need position (the turntable’s fixed location) plus the known, constant rotation rate — no per-measurement orientation is required, since the turntable enforces it:

final double timeInterval = TurntableGyroscopeCalibrator.DEFAULT_TIME_INTERVAL; // seconds

final Collection<StandardDeviationBodyKinematics> measurements = new ArrayList<>();
// ...
measurements.add(new StandardDeviationBodyKinematics(measuredKinematics, specificForceStandardDeviation,
        angularRateStandardDeviation));

final Matrix estimatedMg = calibrator.getEstimatedMg();
final Matrix estimatedGg = calibrator.getEstimatedGg();

Turntable calibrators: constant known rate and Earth rate

Idea

A turntable spinning at a constant, known rate gives a reference magnitude but not the direction of the true rate in the sensor frame, in the same way a static accelerometer gives only the magnitude . The calibrators therefore reuse the norm-based formulation of the non-linear model, with the known rate in place of the gravity norm.

Earth rate removal

Both the turntable and the Earth rotate, so the code first removes the Earth-rate vector. At the given position (NEDPosition or ECEFPosition) it builds a frame whose body axes coincide with the local navigation axes (identity attitude), asks the kinematics estimator for the angular rate that frame senses, and takes that vector (the Earth rate resolved on those axes) as the Earth contribution. Every sample is shifted by it:

so the squared turntable rate is the observation of every measurement. (DEFAULT_TURNTABLE_ROTATION_RATE is the Earth rate and DEFAULT_TIME_INTERVAL is 0.02 s, defaults only.) Only the magnitude of the rate enters, so the sense of rotation does not matter.

The fit is done by LevenbergMarquardtMultiVariateFitter: the inputs of each observation are the two normalized static directions, which stay fixed, and the model output is , compared with . The Jacobian is still numerical, but it is obtained with the JacobianEstimator of irurueta-numerical configured with a relative step and a minimum step of 1e-7, so the step is 1e-7 * max(1, |p|) (with the default, purely relative step, the step vanishes for parameters near zero, which made the fit singular on noiseless data whose true parameters are zero). When a sequence does not carry a gravity-direction standard deviation, it is estimated from the items (accelerometer noise and integrated gyroscope noise), and a value of 1 is used if nothing is available. The robust variants already scored each sequence with the norm of this three-component residual.

Defaults. Following the paper, EasyGyroscopeCalibrator, KnownBiasEasyGyroscopeCalibrator and their robust variants now default to commonAxisUsed = false (full , nine entries) and estimateGDependentCrossBiases = false. The upper-triangular form is only valid for the sensor that defines the body frame, which is the accelerometer, not the gyroscope; and is weakly observable from gravity references alone. Both remain available as options (setCommonAxisUsed(true), setEstimateGDependentCrossBiases(true)). The Turntable calibrators keep their previous defaults.

Differences from the paper (see the Tedaldi notes on the algorithms page): the gyroscope bias is an unknown of this fit (nothing is subtracted beforehand), the residual is a distance between unit vectors rather than between integrated vectors in the paper’s own parametrization, and the defaults are the general (full) matrix without the g-dependent term (see [easy-defaults]). The accelerometer must be calibrated first because and depend on it. KnownBiasEasyGyroscopeCalibrator is the same fit with the bias taken from the caller (6 to 18 unknowns, 9 by default, see Unknowns and minimum data).

Easy example

Each sequence carries the specific-force readings from the static brackets before/after, plus the timed angular-rate samples captured in between:

final List<BodyKinematicsSequence<StandardDeviationTimedBodyKinematics>> sequences = new ArrayList<>();
// ...
final var sequence = new BodyKinematicsSequence<StandardDeviationTimedBodyKinematics>();
sequence.setBeforeMeanSpecificForceCoordinates(beforeMeanFx, beforeMeanFy, beforeMeanFz);
sequence.setAfterMeanSpecificForceCoordinates(afterMeanFx, afterMeanFy, afterMeanFz);

final List<StandardDeviationTimedBodyKinematics> items = new ArrayList<>();
// ...
items.add(new StandardDeviationTimedBodyKinematics(measuredKinematics, timestampSeconds,
        specificForceStandardDeviation, angularRateStandardDeviation));
sequence.setItems(items);
sequences.add(sequence);

// known accelerometer bias/cross-coupling, needed because bg-dependent bias
// requires the true specific force
final Matrix initialBias = new Matrix(3, 1);
final Matrix initialMg = new Matrix(3, 3);
final Matrix initialGg = new Matrix(3, 3);
final Matrix accelerometerBias = new Matrix(3, 1);
final Matrix accelerometerMa = new Matrix(3, 3);

final var calibrator = new EasyGyroscopeCalibrator(sequences, true, false, initialBias, initialMg,
        initialGg, accelerometerBias, accelerometerMa);

calibrator.calibrate();

final Matrix estimatedBg = calibrator.getEstimatedBiasesAsMatrix();
final Matrix estimatedMg = calibrator.getEstimatedMg();
final Matrix estimatedGg = calibrator.getEstimatedGg();

The g-dependent matrix

captures the part of the bias that follows the specific force (typically a mass unbalance in the sensing element): the term adds nine unknowns. It is observable only if the specific force changes independently of the angular-rate information, so the data must be gathered in several attitudes. How each family estimates it:

  • KnownFrame: exactly as in the block above, nine extra columns (stored row by row: ) multiply the known true specific force.

  • Turntable and Easy: through inside the non-linear model, where the specific force is the measured one corrected by the accelerometer bias and cross-coupling. The calibrator reports after the fit. This is why the accelerometer has to be calibrated before the gyroscope (AccelerometerDependentGyroscopeCalibrator).

  • Disable it (estimateGDependentCrossBiases = false) when the data have little specific-force diversity or when the minimum counts in Unknowns and minimum data cannot be met; the g-term is then assumed zero.

Quaternion step integrators

Integrating angular rate over a dynamic interval means numerically solving the quaternion kinematic differential equation

(the matrix is exactly the one built by QuaternionStepIntegrator.computeOmegaSkew; it satisfies ). QuaternionStepIntegrator defines the strategy interface; QuaternionIntegrator drives it over a sequence: for consecutive items it calls the step with the previous rate , the current rate and equal to the timestamp difference, starting from the identity or a given attitude. Every step ends with a re-normalization of the quaternion. Six schemes exist (selected with QuaternionStepIntegratorType, default RUNGE_KUTTA).

Mid-point (MidPointQuaternionStepIntegrator): a half Euler step with the start rate, then a full step with the slope evaluated at the half-step state using the average rate.

The orders in the table come from a numerical experiment run for this page, not from the library tests: the six formulas above were applied to rad/s over 2 s with the rate sampled at both ends of each step, the result compared with a fine reference, and the slope of the log-log error read for 10 to 160 steps. For a constant rate the same experiment gave slope 4 for Runge-Kutta and Suh, slope 2 for Euler and mid-point, and zero error (machine precision) for Yuan and Trawny.

Suh and Trawny are designed to predict the next interval from the previous and the current rate (the weights and the term extrapolate the rate to the middle of the next step). QuaternionIntegrator instead passes the rates at both ends of the interval being integrated, so for these two integrators the rate is extrapolated beyond the interval and the experiment shows first-order accuracy; feeding the same formulas the previous rate and the current rate to advance to the next instant gave second-order accuracy. Prefer Runge-Kutta, Yuan or mid-point with QuaternionIntegrator, and note that the choice matters little when the sampling is fast compared with the rate dynamics (the typical gyroscope case).

EasyGyroscopeCalibrator always integrates its sequences with the Runge-Kutta scheme.

Integrating a sequence directly

QuaternionStepIntegrator.create(type) builds the strategy for one scheme; QuaternionIntegrator drives it step-by-step across an entire BodyKinematicsSequence to obtain the final attitude:

// integrate a whole sequence in one call, choosing the RK4 scheme
final Quaternion initialAttitude = new Quaternion(); // identity
final Quaternion finalAttitude = QuaternionIntegrator.integrateGyroSequenceAndReturnNew(sequence,
        initialAttitude, QuaternionStepIntegratorType.RUNGE_KUTTA);

// or drive a single integration step manually
final QuaternionStepIntegrator stepIntegrator =
        QuaternionStepIntegrator.create(QuaternionStepIntegratorType.RUNGE_KUTTA);
final Quaternion result = new Quaternion();
stepIntegrator.integrate(initialAttitude, previousWx, previousWy, previousWz, currentWx, currentWy,
        currentWz, dt, result);
