Kalman Filtered Estimators

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Classes: INSLooselyCoupledKalmanFilteredEstimator, INSGNSSLooselyCoupledKalmanFilteredEstimator, INSGNSSTightlyCoupledKalmanFilteredEstimator (see the Class Reference table at the end of this page for Javadoc and source links).

What these classes solve

A navigator on its own drifts, because IMU errors are integrated along with the true motion. The Kalman filtered estimators in com.irurueta.navigation.inertial bound that drift by combining the inertial navigation solution with external position/velocity information, following the closed-loop error-state filters of Groves chapter 14 and its Loosely_coupled_INS_GNSS.m / Tightly_coupled_INS_GNSS.m companion scripts (see [book-groves]).

INSGNSSTightlyCoupledKalmanFilteredEstimator

updateBodyKinematics(…​) for IMU samples, updateMeasurements(…​) for GNSS measurements.

How the estimators work

All three estimators follow the same two-rate scheme:

  1. Every IMU sample is integrated. Each sample is corrected with the currently estimated accelerometer and gyroscope biases and integrated with ECEFInertialNavigator over the interval elapsed since the previous sample, regardless of the epoch interval. The estimator therefore always holds the INS-propagated solution. The first sample only sets the time reference, and a sample whose timestamp is not greater than the previous one is ignored (the method returns false).

  2. A Kalman filter epoch is only run when a fix or GNSS measurements arrive. The INS-propagated solution is the predicted state, the fix (or the GNSS measurements) is the measurement at its own timestamp, and the time elapsed since the previous epoch is the propagation interval. The resulting closed-loop correction is applied to the INS solution and to the estimated biases.

flowchart TD IMU["IMU sample at its timestamp"] --> C["Correct with estimated biases"] C --> N["ECEFInertialNavigator:\nintegrate since previous sample"] N --> S["INS-propagated solution\n(position, velocity, attitude)"] FIX["Fix or GNSS measurements\nat their timestamp"] --> G{"At least one epoch interval\nsince previous Kalman epoch?"} G -->|no| X["Ignored, returns false"] G -->|yes| K["Kalman filter epoch"] S -->|predicted state| K K -->|closed-loop correction| S K --> B["Updated bias estimates"] B --> C

The epoch interval (setEpochInterval(…​), or the matching constructor argument) is the minimum time between two Kalman filter epochs. A fix or a set of measurements is ignored when it is older than, or less than one epoch interval after, the previous epoch; one arriving exactly one epoch interval later is accepted (up to the rounding error of the timestamps). The epoch interval does not limit the rate of the IMU samples.

The first Kalman filter epoch propagates the covariance over the time elapsed since the first IMU sample. IMU samples provided before the first fix or GNSS measurements are integrated too, so attitude changes before position and velocity are initialised are kept.

The error-state Kalman filter

The filter does not estimate the navigation solution directly. It estimates the errors of the INS-propagated solution and feeds them back to it (closed-loop correction). In the tightly coupled filter the receiver clock offset and drift are not corrected but replaced by the updated clock states. Usage loop

Feed every IMU sample as it arrives, and every fix or set of GNSS measurements at the timestamp it is valid for. Timestamps are expressed in seconds (or as Time instances) on a common time base.

A fix or a set of measurements is compared against the INS solution at the time of the last provided IMU sample: the solution is not advanced or moved back to the timestamp of the fix. Provide each fix right after the IMU sample whose timestamp is closest to it; otherwise the distance travelled between both timestamps is attributed to INS errors (1.5 m for a 50 ms offset at 30 m/s).

INSLooselyCoupledKalmanFilteredEstimator

// gyro/accelerometer noise and bias PSDs, and fix position/velocity noise standard deviations
INSLooselyCoupledKalmanConfig config = new INSLooselyCoupledKalmanConfig(
        gyroNoisePSD, accelerometerNoisePSD, accelerometerBiasPSD, gyroBiasPSD,
        positionNoiseSD, velocityNoiseSD);

double epochInterval = 1.0; // minimum seconds between Kalman filter epochs
INSLooselyCoupledKalmanFilteredEstimator estimator =
        new INSLooselyCoupledKalmanFilteredEstimator(config, epochInterval);

// initial position, velocity and attitude; the instance is kept and updated in place
estimator.setFrame(initialFrame);

// on every IMU sample (e.g. at 100 Hz)
estimator.update(bodyKinematics, imuTimestamp);

// on every position and velocity fix (e.g. at 1 Hz), at the timestamp of the fix
boolean epochRun = estimator.updatePositionAndVelocity(ecefPosition, ecefVelocity, fixTimestamp);

ECEFFrame solution = estimator.getFrame();                 // corrected INS solution
INSLooselyCoupledKalmanState state = estimator.getState(); // solution, biases and covariance

Without fixes this estimator behaves as a pure inertial navigator. getLastKinematicsTimestamp() returns the timestamp of the last integrated IMU sample and getLastStateTimestamp() the timestamp of the last Kalman filter epoch.

propagate(…​) is deprecated on this class. It no longer runs a Kalman filter epoch (an epoch needs a measurement): it only initializes or synchronizes the Kalman state with the INS solution and always returns false. Use updatePositionAndVelocity(…​) instead.

INSGNSSLooselyCoupledKalmanFilteredEstimator

INSGNSSLooselyCoupledKalmanFilteredEstimator estimator =
        new INSGNSSLooselyCoupledKalmanFilteredEstimator(config, epochInterval);

// on every IMU sample
estimator.updateBodyKinematics(bodyKinematics, imuTimestamp);

// on every set of GNSS measurements, at the timestamp they were taken
if (INSGNSSLooselyCoupledKalmanFilteredEstimator.isUpdateMeasurementsReady(gnssMeasurements)) {
    estimator.updateMeasurements(gnssMeasurements, gnssTimestamp);
}

GNSSEstimation estimation = estimator.getEstimation();
INSLooselyCoupledKalmanState state = estimator.getState();

The measurements are first solved by least squares into a position and velocity solution. The first solution initializes the position and velocity of the INS solution; from then on each solution is used as the Kalman measurement at the timestamp of the measurements — it is not navigated forward in time. propagate(…​) does not run an epoch and always returns false.

INSGNSSTightlyCoupledKalmanFilteredEstimator

INSGNSSTightlyCoupledKalmanFilteredEstimator estimator =
        new INSGNSSTightlyCoupledKalmanFilteredEstimator(tightlyCoupledConfig, epochInterval);

// on every IMU sample
estimator.updateBodyKinematics(bodyKinematics, imuTimestamp);

// on every set of GNSS measurements, at the timestamp they were taken
if (INSGNSSTightlyCoupledKalmanFilteredEstimator.isUpdateMeasurementsReady(gnssMeasurements)) {
    estimator.updateMeasurements(gnssMeasurements, gnssTimestamp);
}

GNSSEstimation estimation = estimator.getEstimation();
INSTightlyCoupledKalmanState state = estimator.getState();

Here tightlyCoupledConfig is an INSTightlyCoupledKalmanConfig. The least-squares GNSS solution is only used to initialize position, velocity and receiver clock offset and drift until the Kalman filter state exists; IMU samples start being integrated once that first solution is available. Afterwards updateMeasurements(…​) runs the Kalman filter epoch directly on the INS-propagated state, using the pseudo-ranges and pseudo-range rates as the measurement, and the attitude is re-orthonormalized after each epoch. propagate(…​) only runs an epoch for measurements that were provided before the estimator was ready to propagate (for example before its configuration was set); measurements already consumed by an epoch are never used twice.

Both INS/GNSS estimators report failures of the inertial navigation or of the filter as INSGNSSException.
