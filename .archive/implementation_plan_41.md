# Implementation Plan

## Task summary

Source: GitHub issue #41
Base branch: develop

Issue #41 ("Fix mistakes and deviations from Tedaldi et al. (ICRA 2014) / imu_tk found in calibration review",
label `bug`, classified as hotfix) lists nine findings (N1-N9) in the IMU calibration code. N1 is a bug that must be
fixed; N2-N9 each need a documented decision. The issue also requires an end-to-end synthetic-data test and a
changelog entry for every default/behaviour change (the `irurueta-navigation-inertial-extra` library depends on them).

Decisions taken with the user during planning:

| Finding | Decision |
|---|---|
| N1 | Fix: default `DEFAULT_USE_COMMON_Z_AXIS = true` in gravity-norm accelerometer calibrators (and robust variants) and norm-based magnetometer calibrators. General (full 3x3) mode is **kept as an option** and documented as defined only up to a rotation. API stays non-breaking. |
| N2 | Fix: easy gyroscope calibrators default to `DEFAULT_USE_COMMON_Z_AXIS = false` and `DEFAULT_ESTIMATE_G_DEPENDENT_CROSS_BIASES = false`; both stay as options. |
| N3 | Fix with the **centred-window detector** (user's choice, best fidelity: exact imu_tk behaviour, symmetric boundaries, static means free of motion samples). `TriadStaticIntervalDetector` classifies the sample at the centre of the window, so status changes are delayed by half a window. Affects every generator using the detector. |
| N4 | Fix: gyroscope sequences are generated only when both neighbouring static intervals are valid; dynamic sequences on both sides of a too-short static interval are joined; the sequence is emitted when the following static interval **ends**, using its accumulated average as the "after" gravity vector. |
| N5 | Fix: 3-component residual (`Rᵀ·u_before` vs `u_after`) with `LevenbergMarquardtMultiVariateFitter` in the four easy gyroscope calibrators and their robust variants; `MINIMUM_SEQUENCES_*` reviewed (current values may stay as conservative minimums). |
| N6 | Fix: `σ/√N` for averaged static measurements; norm-based calibrators give the fitter a standard deviation consistent with the fitted quantity (`2·g·σ_f` for the squared norm, same for the magnetometer); gyroscope sequences get a gravity-direction standard deviation (accelerometer mean noise / g plus integrated gyroscope noise). |
| N7 | Fix: switch `TriadStaticIntervalDetector` to the **variance-norm** statistic of imu_tk (user: best quality regardless of the `-extra` optimizers breaking, they are fixed in a later task). The meaning of every `thresholdFactor` changes (`k_reference ≈ k²` relation recorded in docs/changelog). |
| N8 | Fix: divide by the number of samples actually in the window. |
| N9 | Fix: keep the initialization-period average as the first static average; discard sequences whose preceding static interval has no samples (covered by N4). |

Approach: fix the shared low-level classes first (windowed estimators, defaults), then the detector (N7 + N3), then
the generators (N4, N9, `σ/√N`), then the calibrators' residuals (N5, N6 gyroscope), then the end-to-end test and
documentation. Every behavioural fix gets a test that fails on the unmodified code first (test-first), as in the
archived plan for issue #36.

Open clarifications: none
